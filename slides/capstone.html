Walk through each criterion with one example of full marks: a q02 whose header says "one row per category; shipments summed to the line before the join", and an expected file whose numbers were worked on paper.

The repository counts for 30% of the course, the timed check for 30%, the lab query files for 30% and the live adaptation for 10%: see the README.

Format

Five minutes to adapt one query live, then two minutes of questions

1 · The change

The trainer reads a changed version of one of your ten questions.

2 · The query

You change it, add a fixture row if needed, and run its test.

3 · The reason

You say what changed in the grain or the rules.

Then two minutes on your assumptions note. Expect "where is this rule applied?" and "why did you decide this?"

The changed questions are in the trainer's pack, one per query; choose a query the participant did not pick to show. A query that does not finish in five minutes can still score on what was said.

Timed check · assistant off

Ten questions · 40 minutes

Two printed tables, ten short questions. Predict, explain, write one query on paper.

Laptops closed. Press T to start the timer. Collect the papers when it ends; mark them during the preparation block with the key in the trainer's pack. Two numbers from the course plan, not to be confused: passing the course needs at least 60% on this timed check; outcome LO2 is evidenced by eight of ten correct on it.

Before the first adaptation

Final preparation · 120 minutes

Run uv run pytest capstone/tests -q, fill in the notes, commit and push.

Press T to start. Walk the room: check that every repository is public, that its history has more than one commit, and that data/full/ is not committed. Pull each repository again at the end of the block.

Peer review · 50 minutes

Run a classmate's tests and read one of their queries against the rules

  • Clone the repository of the participant after you in the running order
  • Run its tests; pick one query and check its grain comment against the query
  • Write one strength, one question and one suggestion as an issue on their repository

Pairs follow the running order: 1 reviews 2, ..., 16 reviews 1. The issue stays on the repository as evidence of the review.

Follow-up task · within two weeks

Two new questions from the business orders service, answered the same way

  • The trainer sends two questions after the course; you add q11.sql and q12.sql to your repository
  • Each with its grain comment, its expected rows worked by hand and a passing test
  • About an hour; the commits on your repository are the record that it was done

This is the tracked follow-up task of the course plan (60 minutes of self-study). Note the commit dates when you check it.
